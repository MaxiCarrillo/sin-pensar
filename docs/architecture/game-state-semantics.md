# Game-state semantics

## Current evidence

The setup flow has a transient local roster and an explicit transient owner-player identifier that keeps a successful owner rename coherent with the profile nickname. Turn duration, main-deck card count, a roster-derived team count, and the committed team assignment are also transient setup values. Pure helpers derive all valid counts, balanced target sizes, and exact `team-1` through `team-N` identifiers; they validate ID-based membership and create deterministic or injected-random balanced assignments that preserve every player exactly once. The Teams screen edits a separate local draft that may temporarily contain unassigned or unbalanced membership, while the store accepts only a complete assignment with at least two players per team and a maximum size difference of one.

The private card draft is an explicit per-player `handoff` → `selecting-main` → `selecting-lightning` → `ready` cycle, followed by `complete` only after every player finishes both choices. A single injected-random shuffle deals 10 unique catalog IDs to each player without cross-player repeats. Main quotas remain 3, 4, or 5; reaching the quota stays in `selecting-main` until an explicit confirmation validates exactly that many unique dealt IDs. Lightning selection then receives only the remaining dealt IDs, and a saved player must have exactly one distinct lightning card. Returning to main selection clears lightning; saving is valid only from `ready` and advances immediately to the next roster-ordered handoff. Invalid-phase and incomplete actions are rejected by pure transitions, while route-level private content is locked again on every mount. Roster names or membership, main-card count, team count, and committed team membership changes invalidate the draft. Direct navigation requires a valid owner, 4–20 valid players, a complete balanced team assignment, catalog capacity, and a compatible draft snapshot.

The gameplay state machine is implemented in `src/shared/domain/gameplay.ts` and called by the transient `src/shared/store/gameplay.store.ts`. Creation accepts only a complete compatible draft, a valid roster and committed team assignment, valid 30/45/60-second timing, an exact match between configured and drafted main-card counts, known catalog IDs, and unique nonempty source decks. The main source is the exact union of every confirmed main selection; the lightning source is the exact union of every confirmed lightning selection. The stable gameplay setup key includes roster order and names, ordered committed teams and membership, timer, configured and drafted main-card counts, and completed selections.

The four stages are `Ronda 1 — Hablar`, `Ronda 2 — Mímica`, `Relámpago — Todo permitido`, and the final `Ronda 3 — Sonidos`. Rounds 1–3 rebuild and reshuffle the complete main source; Relámpago uses only the complete lightning source. Normal stages use the configured 30/45/60-second turn duration, while every Relámpago turn overrides it with exactly 10 seconds. Normal correct actions score for the presenting team. A Relámpago correct action pauses active play until its immutable card decision is attributed to a current player, then awards exactly one point to that player's team. Pass always moves the front card to the queue tail without scoring or attribution. Strict team order and per-team membership cursors continue across timeout and stage boundaries; a boundary advances rotation exactly once.

## Implemented invariants

- The discriminated phases are `handoff`, `active-turn`, `lightning-attribution`, `concealed-active`, `time-expired`, `stage-complete`, `game-complete`, and `results`. Invalid-phase actions are rejected; repeated expiry in `time-expired` is an idempotent no-op.
- Reveal is the only transition that starts a new turn. It records an absolute deadline from an explicit finite `now`; scoring and passing use their captured event time and commit synchronously, rejecting pre-turn or non-finite timestamps, accepting the inclusive deadline, and applying expiry only after that boundary. Relámpago attribution freezes the deadline race at that accepted timestamp, rejects expiry while pending, rejects resolutions before the finite pause timestamp, and shifts both timer facts only by a nonnegative attribution duration on award or cancel. The card UI snapshots the outgoing visual before the synchronous commit: pointer releases preserve their drag origin and 180ms ease-out flight, while button and keyboard decisions use a 1800ms control-origin flight. Reduced-motion completion is synchronous and schedules no animation timeout. The presentation timer and motion never own or delay the domain transition.
- Timeout preserves the complete pending queue, including the visible front card. `Mezclar mazo` shuffles only that queue with an injected random source, advances team/player rotation once, clears turn counters, and enters the next handoff.
- Deck exhaustion appends stable turn/stage history immediately. Intermediate stages wait for an explicit prepare action, then rebuild the next complete source, shuffle it, advance rotation once, and enter handoff. Relámpago completion prepares Ronda 3 from the main source. Final Ronda 3 exhaustion enters `game-complete`; only its explicit action enters `results`.
- Scores are cumulative across all stages. Winner calculation returns every team tied at the highest score.
- Card actions include the expected front-card ID, so duplicate gesture completions against a stale card cannot score or pass a second card. Relámpago attribution additionally requires a player with exactly one current team membership; first resolution wins, and stale, duplicate, unknown, or ambiguously assigned resolutions reject.
- Active-route unmount/remount conceals to `concealed-active` without changing scores, pending cards, rotation, or completed history. If attribution is pending, concealment first cancels it and shifts the timer facts by the elapsed pause so the accepted remaining play budget is preserved. Explicit resume restores the active turn only while time remains; otherwise it expires immediately. Neither private branch mounts a catalog record.
- Setup changes clear gameplay. Missing, malformed, empty-team, stale-player, empty-deck, or incompatible state is rejected rather than repaired with fabricated data.

The nickname and avatar profile remains the only persisted state. The Home route edits nickname in local component state and commits it only through profile initialization, which replaces owner/roster/team/draft identity and resets gameplay. `partialize` excludes roster, teams, drafts, and gameplay; reload recovery therefore returns to safe setup rather than restoring private content.
